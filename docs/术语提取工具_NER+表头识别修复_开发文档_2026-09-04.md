# 术语提取工具 NER + 表头识别修复开发文档

日期：2026-09-04<br>
状态：问题已定位，待按供应商新接口完成联调验收

## 1. 背景

第三方 API 供应商迁移升级后，原请求地址、请求体或响应格式发生变化。当前日志表现为 HTTP 200，但 SDK 返回字符串，代码读取 `.choices` 时出现 `AttributeError`，导致 NER 重试并可能退化为空结果；Streamlit 的 AI 表头识别也存在同类兼容风险。

## 2. 需求与验收标准

| 需求描述 | 验收标准量化 |
| ---- | ------ |
| **NER 接口修复**：适配供应商迁移后的 Base URL、请求体和响应结构；CLI 与 Streamlit 使用同一套 NER 调用契约；非 JSON、错误状态和限流响应能够被识别并进入可控重试。 | 1. 使用新接口完成固定回归样本 **5 个 chunk × 3 轮投票 = 15/15**，每次均能解析出 `persons`/`places` 字段；<br>2. 全量日志中 **0 次** `AttributeError: ... choices`；<br>3. 模拟超时、HTTP 4xx/5xx、非 JSON 响应 **3/3** 能输出明确错误并结束重试，不中断主进程；<br>4. CLI 与 Streamlit 各完成 **1 次**真实小批量联调并产出结果文件。 |
| **Streamlit 表头智能识别修复**：适配新接口响应，保留规则/缓存/AI/默认回退链路；识别失败时展示原因并允许人工选择后继续。CLI 不新增自动识别，由 Agent 识别后传入显式列参数。 | 1. 源文件、双语源文件、2 列术语表、8 列术语模板及多语言表头固定样本不少于 **8 组，正确识别 8/8**；<br>2. 缺少密钥、超时、非 JSON 三类异常 **3/3** 显示可理解原因，且人工改列后 **3/3** 可继续运行；<br>3. 识别结果写入缓存后，重复相同文件上下文命中率 **100%**，更换语言对或服务配置不会复用旧映射；<br>4. Streamlit 完成 **1 次**真实 API 小样本验证；CLI 使用 Agent 映射完成 **1 次**显式列参数运行。 |

## 3. 实施边界

- 以供应商最新 OpenAI 兼容接口文档为准，统一核对 Base URL、请求体字段、`Content-Type` 和响应结构；RelayRouter 当前配置使用带 `/v1` 的 Base URL。
- 表头智能识别只属于 Streamlit 上传阶段；CLI 保持显式列参数契约，不重复建设一套识别器。
- API Key 仅保留在进程内存，不写入日志、断点、缓存、配置文件或分发包。

- 离线回归、异常回退和真实 API 联调记录。
