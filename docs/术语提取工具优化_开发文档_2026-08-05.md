## 3. 已实现架构

系统已形成共享核心、双入口的结构：

```text
Streamlit 网页入口 ui/app.py
        │
        ▼
网页适配层 ui/ui_backend.py
        │
        ├─ 配置解析、服务继承与连接测试
        ├─ 模型和 Profile 管理
        └─ 异步任务、进度、断点与结果保存
        │
        ▼
核心流水线 core.main.run_pipeline
        ▲
        │
CLI 入口 cli.py
```

网页与 CLI 已共享 `core.main.run_pipeline`、`PipelineOpts` 和 `save_outputs`。入口层只负责参数收集、前置校验和状态展示，核心处理与导出契约保持一致。

## 4. 关键实现

### 4.1 仅源文件流程

- 参考术语表已从必填项调整为可选项。
- 未提供术语表时，入口已创建仅含“中文术语、英文译文”两列表头的临时工作簿。
- 空术语表场景已跳过 Embedding 数据库的创建与同步，避免复用其他项目的旧术语向量。
- UI 和 CLI 均已调用统一输出函数，生成 `results.xlsx` 和候选术语标注表。

### 4.2 API 配置与安全

- `RunConfig` 已统一管理主生成、NER、Embedding、表头识别 4 组网页服务配置。
- `resolve_service_settings()` 已统一处理辅助服务继承主服务的逻辑。
- 三类辅助服务均可继承主服务的 Key 和地址，也可使用独立配置。
- 四组网页服务均已提供独立连接测试。
- 连接状态已绑定 Key、Base URL 和 Model 的配置哈希；配置变化后旧状态会立即失效。
- API Key 仅保存在当前进程内存；`.ui_config.json` 只保存非敏感字段。
- 旧配置中的敏感字段会在迁移时移除，配置对象和已知 API 错误信息已执行脱敏。
- 源码、持久化配置和分发 ZIP 的凭据扫描结果均为 0 命中。

已支持的环境变量如下：

| 服务 | Key 环境变量 | Base URL 环境变量 | Model 环境变量 |
|---|---|---|---|
| 主生成 | `OPENAI_API_KEY` | `OPENAI_API_BASE` / `OPENAI_BASE_URL` | `OPENAI_MODEL` |
| NER | `NER_API_KEY` | `NER_API_BASE` / `NER_BASE_URL` | `NER_MODEL` |
| Embedding | `EMBEDDING_API_KEY` / `EMBED_API_KEY` | `EMBEDDING_API_BASE` / `EMBEDDING_BASE_URL` | `EMBEDDING_MODEL` / `EMBED_MODEL` |
| 表头识别 | `DETECT_API_KEY` | `DETECT_API_BASE` / `DETECT_BASE_URL` | `DETECT_MODEL` |

CLI 已提供主生成、NER 和 Embedding 的对应参数。表头识别属于网页上传阶段能力，因此未在 CLI 中增加表头识别参数。

### 4.3 AI 表头识别

- 源文件已支持识别中文文本列、文本 ID 列和可选英文列；术语表已支持识别原文列与译文列。
- 识别结果已区分缺少密钥、配置非法、鉴权失败、限流、超时、连接失败、供应商错误、响应非法和映射非法 9 类状态。
- 识别失败时，页面会显示具体原因并回退默认列，不阻断用户手动选择。
- 重试失败时，页面会保留用户的手动列选择。
- schema-v2 缓存已绑定文件类型、顺序表头、前三行样本哈希、规范化 Base URL、模型和 Prompt 版本。
- 缓存未保存 API Key 或原始样本文本。
- 结果读取优先级已设为：相同上下文人工修正 > 内置表头规则 > 相同上下文 AI 结果。

### 4.4 页面与交互

- 页面已使用统一工作台样式，并移除了背景中的“译”字装饰。
- 侧栏已按一级入口、主模型、项目规则、运行参数和辅助能力分组。
- 桌面侧栏 Logo 已设置为 64×64px，顶部留白为 12px；折叠页头 Logo 已设置为 44×44px。
- 上传器、按钮、配置字段和结果列已使用明确的中文业务名称。
- 按钮已覆盖 hover、active、focus-visible 和 disabled 状态。
- 模型、项目规则、Embedding 数据和断点删除已增加确认操作。
- 历史结果与可恢复任务已采用分页展示，每页最多 10 条。
- 720px 以下页面已切换为单列布局，390×844 视口下未发现横向溢出。

### 4.5 结果指标与图表

- 结果页已展示术语总数、术语分类、沿用术语表、AI 生成译文 4 个指标。
- 译文来源图已同时显示数量与占比，不再依赖悬停读取。
- 分类统计已改为横向条形图，为长分类名称保留了阅读空间。
- 分类超过 12 类时，图表显示 Top 11 和“其余 N 类”；完整统计表继续保留所有分类。
- 结果明细已固定中文字段、核心列顺序、列宽和数值格式。

### 4.6 入口对齐与断点

- UI 和 CLI 已对齐可选术语表、列映射、双语、仅提取、NER、Embedding、并发、Token、断点和输出参数。
- UI 启动任务时会复制配置快照，运行中修改设置不会影响该任务。
- 断点恢复会使用用户明确选择的目录。
- 结果保存完成后才会清理对应断点；失败、中断或取消时仍会保留断点。

## 5. 启动与操作

### 5.1 网页入口

```bash
cd "/path/to/Game-Terms-Extraction-Langlobal"
pip install -r requirements.txt
streamlit run ui/app.py
```

Windows 首次使用可运行 `setup.bat`，后续可运行 `run.bat`。Windows 实机启动仍属于第 10 节列出的未验证边界。

### 5.2 CLI 入口

只提供源文件：

```bash
python cli.py --source 原文.xlsx
```

同时提供参考术语表：

```bash
python cli.py --source 原文.xlsx --glossary 参考术语表.xlsx
```

CLI 列索引从 0 开始，完整参数可通过 `python cli.py --help` 查看。

### 5.3 输入与输出

| 项目 | 位置或格式 | 可访问性 |
|---|---|---|
| 源文件 | `.xlsx`，首行为列名 | 必填输入 |
| 参考术语表 | `.xlsx`，包含原文与译文列 | 可选输入 |

## 9. 常见问题与恢复

| 问题 | 原因与处理方式 |
|---|---|
| 只上传源文件后按钮仍不可用 | 主生成服务或必填列尚未配置；页面会列出缺失项，补齐后重新检查按钮状态 |
| AI 表头识别失败 | 根据页面显示的具体原因检查配置；也可手动选择正确列并继续提取 |
| 连接成功状态消失 | Key、Base URL 或 Model 已发生变化，旧状态按设计失效；重新测试当前配置 |
| 任务意外中断 | 在可恢复任务中选择对应断点继续；结果保存成功前断点不会清除 |
| 图表分类过多 | 图表显示 Top 11＋合并项；完整分类可在统计表中查看 |
| live 测试显示 SKIP | 当前进程未提供表头识别或主生成 Key；这属于安全默认行为 |
| 网页无法访问 | 服务未启动时执行 `streamlit run ui/app.py`；确认端口未被占用 |
