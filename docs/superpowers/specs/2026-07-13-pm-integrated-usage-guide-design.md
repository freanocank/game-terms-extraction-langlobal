# PM 整合使用指南设计

## 目标

为游戏术语提取工具及其配套术语标注助手制作一份面向 PM 的单文件离线 HTML 指南。指南以“提取—审核—回流”业务闭环为主线，覆盖手动操作、自然语言 Agent 操作、验收检查与故障恢复。

## 受众与边界

- 主要受众：理解本地化项目流程，但不需要理解 Python、Streamlit 或浏览器存储实现的 PM。
- 主工具：项目根目录下的 Streamlit 游戏术语提取工具。
- 标注工具：`annotation/术语标注助手_v3.0.html` 单文件离线工作台。
- 不纳入常规操作：`scripts/` 和 `annotation/test/` 下的测试、评估、打包及一次性项目脚本。
- 不把内部日志、断点目录、向量数据库或浏览器草稿描述为正式交付物。

## 信息架构

成品为项目 `docs/` 下的单文件离线 HTML，页首提供目录以及主工具、标注工具快速入口。正文按以下顺序组织：

1. 用途与准备
2. 手动启动与完整闭环操作
3. 自然语言 Agent 操作及可复制指令
4. 验收检查
5. 常见问题与恢复

## 操作流程

### 主工具

- Windows 10/11 公共入口：双击项目根目录的 `run.bat`。本机无 Python 时，脚本调用 `setup.bat` 下载 Python 3.11.9 嵌入版、安装 pip 与 `requirements.txt` 依赖。
- 技术入口：从项目根目录安装依赖并执行 `streamlit run ui/app.py`。
- 准备原文 xlsx、术语表 xlsx、OpenAI 兼容 API Token、API 地址、模型和项目 Profile。
- 上传两个工作簿后核对自动识别的原文、Key、术语中英文列；按项目情况选择双语模式或跳过翻译。
- 提取完成后下载标注模板与原始结果。标注模板是后续人工审核的正式接口；原始结果保留调试字段。
- 相同原文和 Profile 可利用 `output/_checkpoints/` 中的断点继续，但断点属于内部恢复数据。

### 标注工具

- 双击 `annotation/术语标注助手_v3.0.html`，无需安装，处理过程不上传数据。
- 先导入原文，再导入主工具生成的候选模板。
- 解释“跳过已有”“仅补空白字段”“覆盖已有”三种合并策略；增量 AI 结果默认推荐“仅补空白字段”。
- 覆盖划词、整行、批量、手动新增、导入合并、编辑、删除、跳转、筛选及审核状态。
- 区分工程 JSON、定时下载备份、浏览器崩溃草稿与最终 8 列 xlsx：只有最终 xlsx 是术语回流交付物，工程 JSON 用于继续标注。

### 回流

标注工具导出的审定 8 列术语表可作为下一次主工具运行的术语表输入，形成持续积累闭环。

## 产物分类

| 产物 | 位置或命名 | 分类 | 用途 |
|---|---|---|---|
| 标注模板 | UI 下载，描述性文件名；磁盘运行目录也会保存 | 可下载、正式中间件 | 导入标注工具 |
| 原始结果 | UI 下载名 `results.xlsx`；运行目录保存 `results.xlsx` | 可下载、辅助结果 | 查看调试和匹配信息 |
| 审定术语表 | `术语表_<时间>.xlsx` | 可下载、正式交付物 | 回流主工具 |
| 标注工程 | `term_project_<时间>.json` | 可下载、恢复文件 | 完整恢复原文、术语和列配置 |
| 自动备份 | 定时下载的工程 JSON | 可下载、恢复文件 | 降低未保存风险 |
| 崩溃草稿 | 浏览器 localStorage | 内部、不可直接下载 | 仅恢复术语库 |
| 运行断点 | `output/_checkpoints/` | 内部、恢复数据 | 主工具断点续跑 |
| 日志和向量库 | `output/` 日志、`database/` | 内部 | 排障与缓存 |

## Agent 操作设计

提供三组可复制指令：

1. 启动与环境检查：指定项目绝对路径、公共入口、依赖、平台和 API 连接检查。
2. 提取执行辅助：指定两个输入文件、Profile、列规则、输出目录、不得泄露 Token、完成后报告结果数与两个输出文件。
3. 验收辅助：核对两个 xlsx 的行数和列名，检查 8 列约定、审核状态、Key/来源原文空值规则，并把无法自动判断的术语质量交给人工确认。

Agent 不代替浏览器中的人工语义审核；标注工具没有命令行公共入口，因此指南不得虚构自动操作路径。

## 验收规则

- UI 完成提示的术语数等于标注模板数据行数。
- 标注模板及最终术语表列名和顺序严格为：`Key值 / 术语分类 / 术语原文 / 术语译文 / 备注 / 来源原文 / 审核状态 / 最新修订时间`。
- 标注工具导入统计中的新增、更新、跳过之和能解释所有有效输入词条；空“术语原文”行不计入有效词条。
- 最终导出数据行数等于标注工具术语库数量。
- 正式交付前“审核状态”中不存在“未审核”。
- 来源原文中确实存在的词条应有可追溯 Key 和来源原文；手动添加且原文不存在的词条允许两列为空，并记录为已知不可验证项。
- 人名、术语分类、译文准确性和上下文适配属于人工语义验收，不宣称可由行数检查证明。

## 故障与差异处理

- API 测试失败、依赖安装失败、Python 下载失败、列识别错误、断点无法继续、浏览器草稿恢复、模板列缺失和大文件问题分别给出恢复步骤。
- 将 `docs/DEPLOY.txt` 中仍有效的安装、配置、启动和排障内容全部并入新指南；新指南验证通过后删除 `docs/DEPLOY.txt`。
- README 当前指向不存在的 `docs/DEPLOY.md`。成品完成后，将中英文 README 的部署/使用指南链接定点替换为新整合指南，避免保留失效入口。
- 部署文档只明确承诺 Windows 10/11。其他平台只记录技术启动命令，不宣称经过正式支持验证。

## 视觉与离线要求

- 优先复制项目内已有 PM 操作指南的视觉模板，再做针对性改造。
- 使用项目 `assets/logo.jpeg`，转为 data URI 内嵌。
- 不引用外部字体、脚本、图片或网络资源。
- 提供响应式布局和打印样式；窄屏下表格可横向滚动，代码和提示词保持可复制与可读。
- 使用紧凑运营手册风格，不制作营销型页面。

## 验证方式

- 静态检查：标题、五个必需章节、内部锚点、提示词槽位、路径、8 列字段、无外部依赖、无旧项目残留文字。
- 行为证据检查：所有命令、按钮、输入、下载名和恢复行为回溯到当前源代码或可观察 UI。
- 视觉检查：桌面和窄屏截图检查溢出、遮挡、表格、代码块和打印样式。
- 链接检查：所有内部锚点存在；本地相对路径仅作说明，不作为在线资源加载。
