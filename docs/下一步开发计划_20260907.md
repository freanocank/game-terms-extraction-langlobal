## P1：术语质量迭代

1. 全表输入预检：工作表、源/目标/Key 列、译文覆盖率、状态与重复记录；区分列映射完成和任务可运行。
2. 建立覆盖本次 532 行的完整人工标准集，包含应提、不应提、边界、类别、来源行与允许译文；不能只审程序已提出来的条目。
3. 本批已用于分析，只作为开发与回归集。另取未参与调参的同类文件做盲测，按模块和近重复文本分组；没有盲测则明确泛化尚未验证。
4. 源文候选生成与目标译文对齐分离。固定源侧分块、NER 和提取请求；空目标不能阻止提取，目标文字不能反推出源文不存在的词。
5. 对齐同时检查同行字面证据与语义完整性，区分有对应、无对应、不确定。无法沿用仍保留源术语，补译仅作为待审建议。
6. 修复离线重放丢工作表名称；比较完整来源字段、Key、字符位置，不只比较候选集合。
7. Profile 增加类别/示例/规则一致性检查；平衡人名、玩法实体、机制属性、任务名和段位示例，避免后缀线索被当成确认人名。
8. 完整基线建立后再比较三票、两票、两票后定向复核。三轮都未生成的词，不能靠降低投票门槛找回。
9. 有界纠正无效响应，保留成功请求缓存；补齐 NER、被拒绝响应和失败请求的用量记录，未知不算 0。
10. 在原生导出函数设置列宽、换行和冻结表头，不追加版式转换脚本，不改变既有标注表列数。

分支测试假设：只改目标列时，源侧请求和缓存标识不变；固定响应或缓存条件下源候选不变，对齐缓存必须失效。不要求独立随机 API 调用逐字一致。目标语义、同形词和不同 Key 的来源不能跨行移植。

- 人工修订与原始结果分开，支持差异预览、撤销、批量操作记录；审核状态与内容版本绑定。

## 每轮验收与恢复开发顺序

固定数据和配置 → 明确假设 → 单一主要改动 → 离线回归 → 有预算的小样本在线对照 → 人工审核差异 → 达标后全量验证 → 独立提交。

- 报告准确率、召回率、F1、分类和对齐正确率，按专名、机制、UI 拆分；不以术语数量、沿用率或三票率代替质量。
- 记录新增正确项、新增误提、修复漏项和新增漏项；AI 补译单独审核。
- 首跑、重试、续跑、人工间隔分别记账；未知用量明确标注。
- 来源、Key、模板契约和关键案例零回归；质量阈值在完整人工基线后冻结，不预先承诺未经测量的百分比。
- 离线重放不能证明新 Prompt 的效果；未审核反馈不自动更新主术语库或规则。

恢复开发时先做 P0 衔接与任务安全，再做质量评测和提取/对齐分离，之后是审核体验、模块化及按需性能优化。所有项目目前均为待实施。
