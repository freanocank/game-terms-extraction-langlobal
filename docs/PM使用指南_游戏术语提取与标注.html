01

用途与准备

Purpose & preparation

这份指南覆盖一条可交接、可验收的闭环：主提取工具从游戏原文与已有术语表生成候选词，标注工具负责人工修订与审核，审定后的术语表再作为下一轮提取输入。

平台边界：正式支持平台：Windows 10/11。其他平台未经过正式验证；仓库只提供通用 Python / Streamlit 技术命令，不代表 macOS 或 Linux 已完成兼容性验收。主提取工具调用外部 API，安装与运行通常需要网络；标注工具本身为离线单 HTML，表格数据不上传。
原文.xlsx + 已有术语表.xlsx → 主工具 · 提取 / 匹配 / 翻译 → 候选术语标注表.xlsx → 标注工具 · 人工审核 → 术语表_*.xlsx ↺ 下一轮术语表输入

工作目录与运行前检查

项目PM 需要确认
工作目录进入同时含 run.bat、setup.bat、ui/、annotation/ 的项目根目录。本文 Agent 指令使用已核验路径：/Users/spellbook/Desktop/Langlobal/Game-Terms-Extraction-Langlobal。
API / 模型准备 OpenAI 兼容的 API Token、API Base URL 与可用模型名。Token 只在可信本机录入，不放进文档、截图或聊天。
Profile确认对应游戏的 profiles/*.yaml 已存在，或准备可上传的 YAML。Profile 决定分类、提取与翻译规则。
原文 xlsx至少有一列待提取中文原文；建议同时保留稳定 Key / ID。双语模式还要有官方英文列。有效数据必须放在第一个工作表，该表首行为表头。
术语表 xlsx第一个工作表至少有可指定的中文术语列和英文译文列，方向为中文 → 英文。主工具只载入中文与英文同时非空的行；任一列为空即跳过。没有历史术语时也要提供一份保留这两列表头的空 xlsx。
工作表限制主工具与标注工具都只读取每个工作簿的第一个工作表；后续工作表不会自动合并或作为回退。原文、已有术语、候选术语都要放在首表。
不变量两个输入都必须是可读取的 .xlsx；列号在 CLI 中从 0 开始。主工具会清理占位符 / 标签，并跳过空值、纯标点与重复原文。

02

手动启动与完整闭环

Manual operation

主工具：安装、设置、提取与下载

首装（Windows 10/11）。在项目根目录先双击 setup.bat。它下载 64 位 Python 3.11.9 Embedded、启用 pip 并安装 requirements.txt；首次安装必须联网。完成后双击 run.bat。
启动。run.bat 会切换到自身所在目录并启动 Streamlit。浏览器未自动打开时，查看终端显示的地址，通常为 localhost:8501。不要关闭承载服务的终端窗口。
其他平台的技术入口。在项目根目录、已有可用 Python 环境时，依次运行 pip install -r requirements.txt 与 streamlit run ui/app.py。这只是源码入口，其他平台未经过正式验证。
配置。进入「设置」，填写 API Token 与 API 地址，选择 / 添加模型；在「高级设置」选择或上传 Profile。侧栏点「测试 API 连接」。测试成功只证明模型列表接口可读，不等于所选聊天、翻译和 Embedding 能力都可用。
上传两份 xlsx。在「运行」页分别上传「原文文件（xlsx）」与「术语表文件（xlsx）」。两个上传位都必填，有效数据必须在各自第一个工作表；术语表中英文任一为空的行不会载入。
人工核对列。确认「原文列」「Key列（可选）」「中文术语列」「英文翻译列」。有官方英文时开启「双语模式」并核对「原文英文列」；只提取不翻译时才开启「跳过翻译」。自动识别失败可能退回默认列，不能跳过这一步。
开始提取。确认页面摘要中的 Profile、模型和并发后点 开始提取。阶段依次显示初始化、加载、LLM 术语提取、匹配与翻译、完成；运行中可取消，但在途 API 请求不保证立即停止。
下载并留档。完成后先核对页面提取数量和预览，再到「结果」下载「标注模板 xlsx」与「原始结果 xlsx」。浏览器副本进入默认下载目录或提示的用户选择位置；项目磁盘副本位于 output/run_YYYYMMDD_HHMMSS/。历史列表只直接下载原始结果；点「加载」后可重新生成候选模板，但须核对当前 Profile 与新文件名，因此仍建议当轮归档。
断点续跑。「运行」页会显示可续传文件及「所有断点」。有输入副本时直接点「继续」；旧断点没有输入时重新上传原文与术语表。恢复时保持原文、术语表、Profile、模型、列设置与模式不变；界面匹配主要依据原文内容和 Profile，不能据此推断其他配置也一致。
首装纠偏：不要只依赖“首次双击 run.bat 自动安装”的旧说明。若电脑已有系统 Python，run.bat 可能直接使用它而不安装依赖；可靠做法是首装先运行 setup.bat。

主工具候选表字段

当前源码生成的候选模板为以下 8 列，所有候选初始均为「未审核」：

Key值 / 术语分类 / 术语原文 / 术语译文 / 匹配来源 / 来源原文 / 审核状态 / 最新修订时间

「匹配来源」记录精确匹配、双语原文、AI 翻译或无需翻译等来源。保留候选表和原始结果，后续追溯时使用。

标注工具：两次导入、审核、保存、导出与回流

打开。双击 annotation/术语标注助手_v3.0.html，建议用 Chrome 或 Edge。它的 Excel 解析库已内嵌，可离线处理；使用浏览器本地草稿时要保持同一浏览器与用户配置。
第一次导入：原文。点 📥 导入原文Excel，选择本轮原文文件。工具只读取第一个工作表；核对 Key列 / 原文列 / 译文列。从原文划词或整行新增时，工具记录实际添加行的 Key 与来源原文；只有来源字段缺失时，导出才尝试首个命中行回填。
第二次导入：候选术语。点 📋 导入术语表，选择主工具下载的候选表。工具只读取第一个工作表；导入只硬性要求「术语原文」列，其他已识别字段按表头读取。导入后的非空 Key / 来源原文在导出时按原值保留。
选择合并策略。「跳过已有」保留本地修改；「仅补空白字段」只补当前空值，适合合并 AI 增量结果；「覆盖已有」会替换已有内容。日常增量优先选 仅补空白字段，覆盖前先保存工程 JSON。
人工标注。逐条核对术语是否应收、分类、译文、备注与来源。可在原文中划词按 A、点行首 ➕、按 Q 批量添加，或在右侧手动新增；E 编辑、D 删除只在原文单元格内选中已存在术语文本时生效，右侧列表使用对应按钮。
审核。右侧 ✓ 在「未审核」与「已审核」间切换；黄 = 未审核，蓝 = 已审核，绿 = 译文在译文列命中。结合状态、分类、搜索和原文 / 译文筛选完成查漏。
保存现场。按 Ctrl+S 或点「保存项目」，下载 term_project_*.json。该工程含原文、术语、分类及列配置，可加载续作或交接。文件进入浏览器默认下载目录或提示的用户选择位置，项目内没有固定副本；默认定时下载工程，浏览器每分钟草稿只兜底术语，不能代替人工归档。
导出审定表。点「导出术语表 (8列模板)」，得到 术语表_*.xlsx。已有非空 Key / 来源按原值导出；只有缺失字段才从原始工作簿首个命中行回填。原文中不存在的手工术语可保持空白。文件进入浏览器默认下载目录或提示的用户选择位置，项目内没有固定副本，必须人工归档。
回流。下一轮把审定表上传到主工具的「术语表文件」。UI 会尝试自动识别「术语原文 / 术语译文」，仍须人工确认。CLI 使用该 8 列表时，中文列与英文列为 0 基索引 --gl-cn-col 2 --gl-en-col 3，不能沿用默认 0 / 1。

标注工具正式导出字段

Key值 / 术语分类 / 术语原文 / 术语译文 / 备注 / 来源原文 / 审核状态 / 最新修订时间
两套 8 列不是同一结构。候选表第 5 列是「匹配来源」，标注工具正式导出第 5 列是「备注」。候选表仍可正常导入，但标注工具不会把「匹配来源」写进备注；需要追溯时保留原始结果和候选表，不要要求两表列名零差异。

04

量化验收

Acceptance checks
关口检查方法通过标准
输入可用列出原文与术语表的工作表，只检查首表；记录首表名、行数、表头和实际列索引，并统计术语中英列完整性。两份 xlsx 都可读，有效数据都在首表；原文列存在；术语中文 / 英文列存在。术语有效行 = 中英同时非空行，任一为空的跳过数已报告；空术语表也保留两列表头。
主工具数量比较完成页数量、results.xlsx 数据行和候选表数据行。三者数量完全相等；差异数 = 0。
主工具文件检查本轮输出目录与下载留档。原始结果和候选模板各 1 份，均可打开；候选表初始「未审核」数 = 总行数。
候选字段按当前主工具契约检查 8 列及映射。列名 / 顺序与本指南“主工具候选表字段”一致；候选 Key / 来源原文与主结果 source_key / source_text 差异数 = 0。source_text 可为清洗文本或双语拼接，不要求等于原始单元格。
导入数量在空白标注项目导入候选表，记录新增 / 更新 / 跳过和右侧术语总数。术语总数 = 候选表非空「术语原文」去重数。若合并旧工程，则用“旧总数 + 新增数”核对并解释更新 / 跳过。
正式 8 列打开 术语表_*.xlsx 的「术语表」工作表。恰好 8 列，顺序如下；数据行数 = 标注工具术语总数。
审核状态按「审核状态」计数。发布版「未审核」= 0；状态空白或非“已审核 / 未审核”= 0。
导入来源保留结合候选表与操作记录，比较人工审定表的非空 Key / 来源字段。有记录时，导入后非空值按原值保留；「仅补空白字段」不得覆盖本地已有非空来源，覆盖或人工修订差异须与记录一致。记录缺失时只能报告值差异，操作路径与差异正当性标“待人工 / 不可验证”，不作为自动硬失败。
表内新增来源按操作记录回查划词 / 整行新增时的实际添加行。Key 与来源对应实际添加行，且该行所选原文列包含术语；不强制要求它是首个命中行。操作记录缺失时标“待人工 / 不可验证”，不据最终表反推。
缺失回填 / 表外手工按操作记录确认导出前缺失状态，并区分原文是否存在术语。有记录时，仅缺失字段按原始工作簿首个命中行回填，已有字段不改；原文不存在的手工术语允许空并进入例外清单。记录缺失时无法从最终 xlsx 反推导出前状态，整项标“待人工 / 不可验证”，不作为自动硬失败。
回流把审定表上传到主工具，仅核对自动识别与手动列选择。UI 正确选中「术语原文 / 术语译文」；CLI 明确使用 --gl-cn-col 2 --gl-en-col 3。
人工语义全查高风险项（空译文、来源缺失、专名）并抽检 min(总数, max(20, 向上取整(总数×10%))) 条。术语边界、分类、译文风格和上下文无严重错误；发现的问题有责任人和修订记录。
Key值 / 术语分类 / 术语原文 / 术语译文 / 备注 / 来源原文 / 审核状态 / 最新修订时间
不能只靠脚本验收：术语是否应收、分类是否符合项目口径、译文是否自然一致，必须人工判断。模型输出具有波动性，仓库没有语义正确率或耗时 SLA；报告应区分自动硬检查与人工结论。

常见问题与故障恢复

Problems & recovery
API 测试失败、401，或测试成功但提取仍失败
回到「设置」核对 API Token、API 地址与模型名，确认网络和配额，再点侧栏测试。连接测试只读取模型列表；主流程还需要聊天、翻译和 Embedding 能力，NER 预扫描还使用固定模型。报告实际失败阶段，不要把 Token 发给他人。
run.bat 双击无反应，或提示缺 Python / 模块
从项目根目录先运行 setup.bat，确认下载与依赖安装均成功，再运行 run.bat。系统已有 Python 时，run.bat 可能不会自动安装依赖；可从终端运行它以保留错误信息。
setup.bat 下载或安装依赖失败
确认可访问 Python 与依赖源、磁盘空间足够，再重跑 setup.bat。不要删除可用的 python/ 目录或改写 requirements 来掩盖错误；仍失败时把失败步骤和完整脱敏错误交给技术负责人。
浏览器没有自动打开主工具
保留终端窗口，等待 Streamlit 启动后打开终端显示的本地地址，通常是 localhost:8501。若仍打不开，检查终端是否退出、端口是否冲突，再按实际端口访问。
自动识别的列不对
在「运行」页手动选择原文、Key、官方英文、术语中文和术语英文列；CLI 列号从 0 开始。不要直接开始提取。标注工具也要分别核对 Key / 原文 / 译文列。
中断后没有从预期位置继续
在「所有断点」查看状态，单位是 chunks，不是 Excel 行。恢复时使用完全相同的原文、术语表、Profile、模型、列设置与模式。断点通常每若干批写入，最近一批可能重做；成功完成后 UI 会清除断点。
标注工具提示恢复草稿
确认时间与术语数后恢复，再重新导入原文并核对三列。浏览器草稿只含术语，且受本地存储配额约束；立即另存 term_project_*.json，后续以该工程文件为正式续作依据。
导入术语表提示缺列
标注工具硬性要求「术语原文」表头；缺失就停止。主工具作为术语表输入则必须同时能指定中文与英文两列。先复制备份，再由负责人修正表头；不要把报错改写成兼容。
候选表是“匹配来源”，导出表却是“备注”
这是当前两工具的已验证接口差异，不是文件损坏。候选表可以导入，但“匹配来源”不会写进备注。追溯依赖原始结果 / 候选表；正式交付使用标注工具导出的“备注”结构。
大文件处理慢、页面像是停住
主工具保留服务终端并观察阶段 / 断点，不要只关闭标签页来假定任务已取消。标注工具导入大量数据后等待“索引就绪”，分阶段保存工程 JSON；浏览器草稿不含原文，内存或配额不足时按负责人批准拆分批次，并在最终合并时重新核对数量。
结果页找不到上次的候选模板
历史列表只直接提供原始 results 下载；先点该记录的「加载」，进入结果视图后可重新生成候选模板。重新生成前核对当前 Profile，下载后核对 8 列、行数和新文件名；也可优先使用 output/run_*/ 的当轮磁盘副本。
恢复原则：保留原输入、断点、原始结果、候选表和最近的工程 JSON；先定位失败阶段，再重试。任何重试都要在报告中与首次运行数据分开记录。
